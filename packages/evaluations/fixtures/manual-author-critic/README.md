# Manual author–critic refinement reference

This fictional reference shows the target for alternating manual author and
critic work: a complete, relevant CV whose claims stay linked to career facts,
whose requirement gaps remain visible, and whose proposed changes are reconciled
with the candidate in control. It is reference material, not a provider
transcript, runnable evaluation, or measured parity result.

## Use

Use only `careerFacts` and `opportunity` from [case.json](case.json) as drafting
inputs. Keep `referenceCv` and `reviewExpectations` out of model inputs; they are
the authored comparison and review guide. Use the fact, requirement, and
statement IDs to illustrate source-backed critique, evidence-based revisions,
and explicit unresolved gaps. A candidate may accept, reject, or leave each
proposed reconciliation open.

The reconciliation examples are hypothetical, not recovered messages or an
actual model interaction. User-reported manual back-and-forth is the motivation
for this reference, not evidence of factual correctness, an interview or offer,
workflow parity, or measured effort. The data does not claim that new product
features implement this loop or that the example establishes knowledge-base
lineage in a live run.

## Fictional scope and limits

This is a fictional reconstruction, not a real CV with names replaced.
Organisations, project domains, relative chronology, and achievements have been
recomposed; originals remain private and are not included. The fixture contains
no contacts, URLs, filesystem paths, exact outcome metrics, or source
checksums.

No provider run, actual transcript, model identity, historical iteration
history, measured effort, or real application outcome is represented. Do not
use this file as a runnable `EvaluationCase`, training upload, successful pilot,
or evidence that a candidate received an interview or offer. The reference CV
and review labels are authored expectations, not candidate judgments or
measured results.
