# Synthetic matched application reference

`case.json` contains fictional career facts, a matching opportunity, a reference
CV represented as sourced statements, and human-review expectations. It preserves
useful evaluation problems from a candidate-authorized example: substantive
selection, explicit ownership, mature versus experimental work, and corrections
that must survive drafting.

This is a synthetic reconstruction, not the real CV with names replaced. People,
organisations, project domains, chronology, and achievements have been replaced
or recomposed. Contact details, locations, URLs, private narrative, distinctive
metrics, and original document text are not included. Originals and pseudonymized
working copies remain outside the repository.

## Use

Use the facts and opportunity as drafting inputs. Keep the reference CV and
review expectations out of model inputs when measuring independent generation.
Compare generated claims with the fact IDs, check the forbidden overstatements,
and have a reviewer assess selection and explanatory depth. The coverage labels
are authored expectations; they are not candidate judgments or a new numeric
readiness rubric.

The file is reference data, not a runnable `EvaluationCase`: it has no generated
first/revised draft, provider execution, measured effort, or real application
outcome. An evaluation must declare those settings and acceptance criteria before
running. Do not count this fixture as a successful pilot or infer that the
real-world application led to an interview or offer.
